# Founding XI — What We Measure

Eleven players. Every query below runs in the Supabase SQL editor with
the service role — no dashboard product needed at this scale, and no
vanity metrics wanted at any scale. The one question behind all of
them: **which parts of MIDO correlate with a player coming back?**

Sources: `auth.users` (signups), `product_analytics` (named product
actions — migration 0033), `beta_feedback` (what they tell us). The
football event log is **not** queried for metrics; it belongs to the
players.

---

## Day 1 — did they onboard?

```sql
select u.email, u.created_at::date as joined,
       exists(select 1 from product_analytics a
              where a.user_id = u.id and a.event = 'onboarding_completed') as onboarded
from auth.users u order by u.created_at;
```

A founder who signed up and did not onboard is a phone call, not a
statistic.

## Weeks 1–2 — are they returning?

Active day = any product action that day.

```sql
select u.email,
       count(distinct a.created_at::date) filter (where a.created_at >= now() - interval '7 days')  as active_days_7,
       count(distinct a.created_at::date) filter (where a.created_at >= now() - interval '14 days') as active_days_14,
       max(a.created_at)::date as last_seen
from auth.users u left join product_analytics a on a.user_id = u.id
group by u.email order by last_seen desc nulls last;
```

## The core loop — who has closed it?

The product's promise is the loop, not any feature. A player who has
done all five has experienced MIDO; a player stuck at one or two shows
us exactly where the product loses people.

```sql
select u.email,
       bool_or(a.event = 'goal_created')            as goal,
       bool_or(a.event = 'study_completed')          as study,
       bool_or(a.event = 'match_review_completed')   as review,
       bool_or(a.event = 'training_completed')       as training,
       bool_or(a.event = 'film_uploaded')            as film
from auth.users u left join product_analytics a on a.user_id = u.id
group by u.email;
```

## The Next panel — is the intelligence trusted?

```sql
select event, count(*) from product_analytics
where event in ('recommendation_completed', 'recommendation_dismissed')
group by 1;
```

Read completed:dismissed as a ratio, per week. Rising dismissals are
the scorer being wrong in ways the journey tests did not anticipate —
that is a bug report, generated by behavior.

## AI usefulness — the thumbs

```sql
select subject,
       count(*) filter (where rating = 1)  as useful,
       count(*) filter (where rating = -1) as not_useful,
       array_agg(body) filter (where rating = -1 and body is not null) as reasons
from beta_feedback where kind = 'ai_rating'
group by subject;
```

The `reasons` column is the most valuable text the beta will produce.

## Value — what correlates with returning?

At n=11 this is read by eye, not by statistics: put the core-loop table
next to the active-days table and look. If every retained player has
uploaded film and no churned player has, that is the finding. Resist
computing correlations on eleven people — the honest instrument at this
scale is the founder call, informed by these tables.
